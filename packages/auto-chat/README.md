# auto-chat（soapbot 插件）

让机器人在被显式开启的会话里偶尔自己开口。三道自我克制：会话白名单（宿主 ledger +
插件自己的 /autochat-set 双层）、频率硬上限（≥4 小时间隔、每天 ≤2 条、每轮全局一个
会话）、温度阈值（低于不开口）。

## 命令

| 命令 | 作用 |
|---|---|
| `/autochat-set [阈值]` | 在当前会话开启（阈值 0-1，默认 0.6） |
| `/autochat-off` | 关闭 |
| `/autochat-clear` | 清空话题片段与计数 |

## 温度模型（确定性，可复算）

`warmth = log1p(近7天交互数)/log1p(200) × 0.5^(距上次交互天数/7)`。钩子计数、
cron 判断，全部在本插件内；宿主级跨插件温度是下一批（见 main 仓库
docs/qq-autonomy-design.md §4）。

## 重启语义（worker 重启后哪些状态还在）

worker 重启后（宿主重启 / 插件重载）：

- **保留**：storage 里的全部状态（开启的会话、话题片段、温度计数、冷却时间戳）
  ——都在加密 storage 里，重启自动恢复；
- **丢失**：正在进行的 SSE 无——本插件没有长连接；轮询计时器由宿主 cron 驱动，
  重启后自动继续；
- **语义**：重启后温度计数从 storage 读回，不会把一个聊了三天的会话当成新会话；
  也因此不会出现「重启后立刻连发」——冷却时间戳同样持久化。

## 能力与边界

| 能力 | 用途 | 收窄 |
|---|---|---|
| `message` | 钩子计数 + 攒话题片段（前 120 字符） | 原文不落盘 |
| `storage` | 配置/片段/计数（加密） | 只存片段与统计 |
| `cron` | 每 30 分钟一个 tick | 每轮全局只挑一个会话 |
| `send` | 主动发言 | 只发开启且观察过的会话 |

无模型调用：开口来自话题片段 + 固定模板。判断标准硬编码。
