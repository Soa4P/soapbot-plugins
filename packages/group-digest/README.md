# group-digest

群活跃度统计——「这个群最近聊得怎么样」的确定性回答。改编自 AstrBot 群分析总结（432★）的**确定性残量**：上游是拉群历史消息 → LLM 时间线摘要 → 定时推送日报/周报；本插件不读消息文本、不做模型调用、不主动推送，把能确定性做的部分做成会话级统计面。

## 边界决定形态

| 上游机制 | soapbot 形态 | 原因 |
|---|---|---|
| LLM 时间线摘要 | 不做——消息内容的回顾与摘要是记忆类插件（memory-weekly ／memweek）的面 | 插件无模型面 |
| 定时推送日报/周报 | 不做——`/digest-now` 随要随算，不沉淀 | cron 无会话范围（宿主钉死 scope）；定时推内容属待拍板的写面边界 |
| 拉历史消息 | 消息钩子**现场攒计数** | 只存计数与显示名，不存消息文本（比 memory-weekly 的片段存储敏感度更低） |

**统计口径（重要）**：宿主把未 @ 机器人的群消息挡在插件执行面之外（`SkipReplyStage` 在
消息钩子之前——隐私默认：插件永远看不到没人叫机器人时的聊天）。所以本插件的计数只
覆盖**被唤醒的消息流**（@ 机器人或触发唤醒词的消息），不是群里的全部消息量；「日均/
最活跃时段/活跃成员」都是这个口径。想要全量群消息统计，需要宿主侧提供匿名列计数的
专用面（设计输入，未拍板）。

## 命令

| 命令 | 作用 |
|---|---|
| `/digest-now [天数]` | 活跃概览：近 N 天（1..14）消息量、日均、最活跃时段 top3、发言成员数与最活跃成员 top5。每次现算，不沉淀摘要产物 |
| `/digest-reset` | 清空本会话统计 |

## 能力与边界

| 能力 | 用途 | 收窄 |
|---|---|---|
| `message` | 钩子累计计数 | 只存计数、时段与显示名，不存任何消息文本；14 天滚动窗口 |
| `storage` | 每会话一份计数（加密） | 成员计数上限 200，超出淘汰次数最低者 |
| `command` | 两条命令 | 只读本会话（caller 的 session_key 由宿主绑定） |

## 双模式存储

进程内 storage 是同步 API，隔离 worker 的 `_RemoteStorage` 是 async——所有 storage 调用经 `sget`/`sset` 助手（isawaitable 则 await），进程内与隔离两种模式同一份代码；setup() 阶段不做 storage 访问（隔离模式 boot 期没有活跃请求）。

## 适配说明

改编自 AstrBot Cloud 市场群分析总结插件（432★，见 soapbot 仓 docs/reference-batch11 报告 §2.1）。上游的 LLM 摘要与定时推送两项是宿主边界设计输入，已登记进报告；本插件是其确定性残量的落地形态。
